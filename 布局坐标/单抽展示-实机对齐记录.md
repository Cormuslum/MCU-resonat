## 四、两个反直觉结论（下次别再踩）

### 1. 属性标签的配色是语义色，属性面板的配色**不是**

属性标签（`tag01..05`）采样后完全符合五维语义，且被两张实机截图双向验证：

| 属性 | 素材 | 均色 | 实机验证 |
|---|---|---|---|
| 甜美 | tag-1 | `#f7aaae` 粉 | — |
| 典雅 | tag-2 | `#ddb072` 金 | ✅ 俏皮黑桃 |
| 清新 | tag-3 | `#9db891` 绿 | ✅ 山林地印迹 |
| 性感 | tag-4 | `#b892c1` 紫 | — |
| 帅气 | tag-5 | `#88a7c9` 蓝 | — |

但**属性面板**（`board_01..04`）跟属性无关，是「典雅→board-3、清新→board-2」这种实测顺序：

| 截图 | 属性 | 拟合 MAE（board1/2/3/4） | 结论 |
|---|---|---|---|
| 俏皮黑桃 3★ | 典雅 | 36.6 / 20.9 / **14.9** / 52.3 | board-3（蓝灰） |
| 山林地印迹 4★ | 清新 | 23.4 / **18.7** / 25.3 / 53.2 | board-2（紫） |

按「颜色语义反推面板」会得到棕色面板，错得很明显。映射表写在 `GachaView.vue` 的 `BOARD_BY_STAT`。

### 2. 解包背景 `bg` + `bg_right` 拼不出实机背景

`T_showpic_clothes_bg.png`（155×87）和 `T_showpic_clothes_bg_right.png`（1188×1080）**单独看都是暖棕**，
叠起来仍然偏棕；实机是「上紫下暖」。用户合成的 `bg_reward.png` 才是对的（左上 `51,45,60` 偏紫）。

而且底板把 `bg` 底部那条 `237,212,157` 的暖白带压掉了，必须用
`bg.webp` 全屏 `mix-blend-mode: screen` 叠回去 —— 但**不能整屏叠**，
实机右下角（x>1600）仍然是很暗的紫，所以要用椭圆遮罩圈在左下：

```css
mask-image: radial-gradient(ellipse 1400px 760px at 36% 106%,
  #000 0%, #000 34%, rgba(0,0,0,.55) 60%, transparent 82%);
```

这一步把「额外获得条」区域 MAE 从 30.0 压到 8.5。

## 五、踩过的坑

| 现象 | 根因 | 改法 |
|---|---|---|
| 卡片（金框+立绘+金线+丝绸）**整体消失** | 全局 reset 有 `img{max-width:100%}`，`.dt-cardwrap` 是 `0×0` 容器，百分比算成 0 宽 | `.dt-cardwrap > * { max-width: none }` |
| 底板加载成纯色，naturalWidth=0 | Vite dev server 缓存了写入一半的 public 文件 | 重启 dev server |
| 金框位置比实机偏右下 4/9px | 「界面标注」表写的 429×589@431,259 是缩放推算值 | 模板匹配 436×600@427,250 |
| 立绘被当成「需要放大 1.28 倍」 | 早期比对时把素材缩到一半看，产生错觉 | 模板匹配确认 **1:1 不缩放**，420×585@435,257 |
| 名称/文字整体偏高 4~7px | 换成方正雅士黑后字体 ascent 不同 | 按实机墨迹 bbox 逐个调 `top` |
| 星级按「核心宽 86」反推步距 27 | 三颗星重叠后核心宽 ≠ 单颗显示宽 | 四组参数实测，步距 34 最优 |

## 六、字体

解包 UI 全篇用 **方正雅士黑**（`FZYASHJW_Cu.ttf`，8371 字），项目此前用的是 Noto Sans SC 兜底。

- `public/assets/fonts/yahei-bold.ttf`（Cu）/ `yahei-medium.ttf`（Zhong）
- `global.css` 注册 `@font-face { font-family:'NikkiYaHei' }`，body 字体栈首位
- 覆盖率：全项目 3076 个汉字里只缺 **翙、蹚** 两个生僻字，由 Noto 兜底
- `collect-assets.py` 的 `FONT_MAP` 已加入这两个文件
