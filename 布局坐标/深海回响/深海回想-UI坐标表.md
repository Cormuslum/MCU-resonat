## 一、数据来源与坐标换算

| 项目 | 说明 |
|---|---|
| 实机截图分辨率 | 1918 × 1078 px |
| 解包表设计分辨率 | 1920 × 1080 px |
| 横向换算系数 | 1920 / 1918 ≈ **1.00104** |
| 纵向换算系数 | 1080 / 1078 ≈ **1.00186** |
| 结论 | 两套坐标**近似 1:1**，实机截图像素坐标可直接对照解包设计坐标，误差 < 2 px |

- 坐标约定：`(x0, y0)` 为左上角、`(x1, y1)` 为右下角，均从画面左上角 (0,0) 起算（与解包表一致）。
- 解包表仅收录 **带贴图/材质的 Image 类节点**；TextBlock（文本）、布局容器、非贴图动效节点不在表内。因此实机截图中的全部文字（标题「深海回响」、次数「0」、节点「5次/15次/25次」、角标「1」、「5次后可领取」、UID）在解包表中无对应行，以下按**截图实测**给出位置。
- 实机截图的环体、光轨、卡片均带动态辉光，边界为软过渡，坐标取**视觉主体范围（±10 px）**，不代表硬边矩形。

## 四、坐标换算方法（解包表 → 实机截图）

解包表原坐标为 1920×1080 设计分辨率下的绝对像素，实机截图 1918×1078，换算公式：

```
实机截图坐标 ≈ 设计坐标 × (1918/1920, 1078/1080) ≈ 设计坐标 × (0.99896, 0.99815)
```

即两套坐标几乎重合，直接对照即可；如需精确换算，按上式逐点计算。

UMG 布局换算原理（来自解包表附注，供复核）：
`x0 = Min.X×W + Left；y0 = Min.Y×H + Top；x1 = Max.X×W + Right；y1 = Max.Y×H + Bottom`，再按 Alignment 平移（W=1920、H=1080，换算已在解包表中完成）。

## 五、注意事项

1. **精度**：实机截图为游戏渲染画面，UI 带辉光/粒子动效，上表坐标取视觉主体范围，误差约 ±10 px；解包表坐标为设计布局值，两者差异属正常。
2. **TextBlock 缺失**：所有文字元素（U2、U4、U7~U9、U11/U13/U15 角标、U16、U17）在解包表（仅 Image 节点）中无对应行，位置以截图实测为准。
3. **事件专属 UI**：标题徽章（U1/U2）、累计圆盘（U3~U5）、轨道节点与奖励卡片（U7~U16）为「深海回响」活动专属界面，由非 Image 节点与活动素材拼装，未收录于解包 Image 表。
4. **右侧区域**：x > 1270 区域（右上、右中、右下）无交互 UI，仅有背景星点与光带（见 3.2 节）。
