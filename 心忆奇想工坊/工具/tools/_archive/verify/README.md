# 历史验收脚本（归档）

这里放 **v2.3 ~ v2.0.04** 的一次性版本验收脚本，共 37 份（2026-11-12 归档）。

## 为什么归档

`tools/verify-*.mjs` 曾经每发一版就加一份，最终 50 份堆在 `tools/` 根下，
每次列目录都要在一堆 v2503 / v2701 里找现行脚本。归档后：

- **`tools/` 下只留 13 份**能当回归套件用的（功能域验收 + 最近三个版本）；
- 归档的这些记录的是「当时那一版该长什么样」，**不是现行行为契约**。

## 怎么跑

```bash
# 一律从**项目根**运行（脚本内用 process.cwd() 定位素材与源码）
node tools/_archive/verify/verify-v2503.mjs
```

- 多数要 dev server 在跑（`npm run dev`，`http://127.0.0.1:5178`）；
  带工坊交互的还要工坊在跑（`npm run up`，5199）。
- 有 4 份（v2810 / v2914 / v2922 / v2923）用 `await import('../../updater/lib/…')`
  直接取工坊模块 —— 归档时已经把 `../updater/` 改成 `../../updater/`，
  直接跑就行，**不要**再把它们复制回 `tools/`（那样反而会找不到 updater）。

## 已知会 FAIL 的断言（属预期，不是故障）

归档脚本按当时的目录结构 / 素材数量写死，跟现在的仓库对不上：

- 图鉴标题索引 `src/data/reading-titles.ts` / `story-titles.ts` **已删除**
  （v2.1.04 起标题并入运行时 `public/assets/data/{stories,readings}.json`）。
  v2923 / v2924 已在归档前改读运行时 JSON，其余老脚本没动 —— 它们只读 `src/data/*.ts` 的
  正文，不受影响。
- 写死数量的断言（593 篇阅读物、134 篇故事、88 座阁…）会随素材增减而 FAIL。
- 检查已删目录（`卡池横幅/`、`素材/信息表/前后名称对照表.md` 等）的断言必然 FAIL。

**结论**：这里的 FAIL 只说明「当时的判据不适用于现在」，不要据此改代码。
要验现行行为，用 `tools/` 下保留的那 13 份。
