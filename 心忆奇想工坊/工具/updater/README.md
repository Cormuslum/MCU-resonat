# 心忆奇想工坊 · 使用说明

> 独立于抽卡模拟器的更新自助程序。把素材拖进来、填写元数据。
> 服装图鉴 / 故事图鉴 / 阅读物图鉴一起更新，写完自动跑数据管线。
>
> 素材版权归叠纸所有，本项目仅用于个人学习，非商业、非盈利。

## 启动

```bash
node updater/server.mjs          # 起服务并自动打开浏览器（http://localhost:5199）
node updater/server.mjs 5200     # 换个端口
UPDATER_NO_OPEN=1 node updater/server.mjs   # 不自动开浏览器
```

**零依赖**：整个程序只用 node 内置模块（`node:http` 静态服务 + SSE 日志），
不装任何 npm 包。Python 只被既有的素材管线用到（`python` / `py` / `python3` 会自动探测）。

它和模拟器互不影响：模拟器是 vite dev server（5178），更新工坊是 5199。

## 三步用法

1. **选一件事**：左边挑「版本 / 服装阁 / 套装 / 故事 / 阅读物」。
2. **填几个字 + 拖素材**：版本号、阁名、套装名这些猜不出来的必须填；
   图片可以整套从资源管理器拖到页面上（或某个具体槽位），也可以把完整路径粘进
   底部的「按路径读取」输入框（支持一次多行、支持文件夹）。
3. **预检 → 写入并更新**：预检看缺什么；写入走「归档素材 → 跑数据管线 →
   （可选）重启模拟器」。全程日志在底部控制台实时滚动。

## 素材规格速查

下文路径均相对数据根（`信息表/`、`服装阁/`、`套装库/` 所在的那一层）；
`public/assets/**` 指模拟器目录下的成品目录。

拖进来的图按**尺寸 + 文件名**自动识别归类（识别不准的会进「待分配」手动指定）：

| 素材 | 规格 | 落到 |
|---|---|---|
| 版本缩略图 | 672×188 | `界面/UI整包/UI/Image/Card/T_UI_Friends_Card_img_NNN.png` |
| 版本大图 | 1532×860 | `界面/UI整包/UI/Image/Card/T_UI_Pear_Card_img_NNN_L.png` |
| 服装阁背景 | 1920×1080（或 1000×500 的列表图，自动裁 16:9） | `服装阁/<版本>·<版本名>/<阁名>/背景图.png` |
| 列表缩略图 | ≈320×140 | `服装阁/<版本>·<版本名>/<阁名>/列表缩略图.png` |
| 阁名艺术字 | 横长透明图 | `服装阁/<版本>·<版本名>/<阁名>/艺术字.png` |
| 套装铭牌 | 332×96，文件名含 `name` | `界面/UI整包/UI/SysResonance/texture/Pic/<编号>/T_UI_resonance_gacha_NNN_nameNN.png` |
| 深海回响奖励 | 256×256，文件名「120抽-XXX.png」（只收 120 抽及之后的里程碑；低抽数全阁共用一张，不用给） | `服装阁/<版本>·<版本名>/<阁名>/深海回响/` |
| 套装立绘 | 448×656 竖图 | `服装阁/…/<阁名>/<套装>/进化等阶/整体-初始.png`（焕新 / 一进 / 二进 / 满进 同目录） |
| 部件试穿图 | 520×724 | `服装阁/…/<阁名>/<套装>/半身像/<部位>-<部件名>.png` |
| 部件图标 | 256×256 | `服装阁/…/<阁名>/<套装>/图标/<部位>-<部件名>.png` |
| 套装数据 | `属性-*.yaml`（官方原样收） | `套装库/<套装ID>.yaml`（属性 + 文案合并，跑完管线即删） |
| 套装故事 | `.md` | `故事/故事-X星-<套装>.md` |
| 阅读物 | `.txt`（含【编号】头）或直接粘正文 | `阅读物/<区域>/《书名》.txt` |

约定：

- **阁内套装按「5★ 在前」填写顺序**，专属铭牌按这个顺序编号（name01 = 第一套 = 5★）。
- 版本卡编号、服装阁编号（官方）**留空即自动取**（取当前最大值 +1）。
- 服装阁的唯一编号就是官方 gacha 号（`banner-081`）。
- 没给套装 YAML 时，会按部件图标生成最小版（部件名/部位齐全，五维空），图鉴里不会缺行。
- 没给服装阁背景 / 艺术字不阻断更新，界面有兜底（深色渐变 / 纯文字标题），预检会提示。

## 写入了哪些地方

每个任务的「这次会写入」区块实时列出（随填写内容变化）。典型的一次新建服装阁：

```
信息表/服装阁索引.json             ← 新阁登记（版本 / gacha 编号 / 阁型）
信息表/自建内容.json               ← 登记为自建；只有自建内容能在工坊里改
信息表/套装序列.csv                ← 阁内每套一行
服装阁/<版本>·<版本名>/<阁名>/      ← 背景图 / 列表缩略图 / 艺术字 / 深海回响 / 各套装目录
界面/UI整包/UI/SysResonance/texture/Pic/<编号>/   ← 套装铭牌
视频/服装阁动态/<阁名>.webm|mp4    ← 动态背景（给了才写）
套装库/<套装ID>.yaml               ← 套装数据，信息编进 pool-map 后即删
pool-map.json · public/assets/**   ← 管线产物
```


## 扩展包（DLC）

「更新」不再直接改共享的素材库 + 全量重建管线，而是产出一个**自包含的包**：

```
updater/dlc/<id>/        源包区（工坊编辑 / 打包 / 上传）
  dlc.json               清单：provides[]（接口声明）+ mount 决策
  data/<接口>.json       每个接口一份结构化数据
  assets/**              素材副本（已转码的 webp）

public/dlc/<id>/         运行区（模拟器运行时 fetch）
public/dlc/index.json    已装包索引 + 挂载开关
```

**包自带素材**，所以拷给任何装了本模拟器的人都能直接用，不依赖对方机器的素材库。

### 五个挂载接口

接口是包与模拟器之间**唯一的契约** —— 模拟器只认接口名，不认包内部结构。

| 接口 | 作用 | 挂载到哪 |
|---|---|---|
| `pool.banner` | 一整个阁（含套装） | 共鸣页多一阁 |
| `pool.set` | 一套服装 | 指定服装阁的套装列表 |
| `codex.story` | 一篇套装故事 | 故事图鉴 |
| `codex.reading` | 一篇阅读物 | 阅读物图鉴 |
| `version.banner` | 一个小版本（含缩略图 / 大图） | 版本页 |

**挂载决策有三层**（后者覆盖前者）：

```
运行区索引的接口级开关  >  包内 provides[].mount  >  默认挂
```

所以「装上但不生效」「只挂故事不挂套装」都能做到 —— 由包作者决定，也能在工坊里改。

### 用法

左栏最后一项「扩展包」：

1. **做一个包** —— 从库里切（服装阁 / 套装 / 故事 / 阅读物 / 版本），自带素材副本；
2. **本机的包** —— 装 / 卸 / 打包 zip / 上传 / 删除，外加整包与每个接口的开关；
3. **云端 / 网盘** —— 配远端、上传、列远端包、下载并安装。

顶栏的**上传 / 下载**两个圆钮就是这块面板的快捷入口。

### 远端

| 类型 | 说明 |
|---|---|
| `local` | 本地目录（网盘同步盘 / 共享盘 / U 盘）。文件拷过去 + 自动维护 `index.json` |
| `http` | 通用 HTTP 端点：POST `/upload`、GET `/index.json`、GET `/<id>.dlc.zip` |
| `git` | git 仓库：`git add / commit / push` |

配置存 `updater/remote.json`（面板里可改）。

### 删除目录的正确姿势

别直接用 `fs.rmSync(dir, { recursive: true })`：某些运行环境（safe-delete shim，
通过 `NODE_OPTIONS` 注入）会把它改成回收站语义 —— 删除变成异步（刚调完 `exists()` 目录还在，
代码误判成删不掉并抛错，但目录其实已经空了）、每文件约 260ms、偶尔整批失败。

统一用 `lib/dlc.mjs` 的 `dlc.rmTree(dir)`：按「原生子进程 → 直接 `rmSync` → 手写逐层 walk」
三级递进，每级之后轮询确认目录真的消失才算成功。

`uninstall()` 里也做了配套处理：运行区目录删不掉时照样把索引条目摘掉，
否则模拟器会读到一个「装了但文件不在」的包。

## 快照与回滚

每次「写入并更新」都会先把要改的文件原样备份到 `updater/.snapshots/<时间戳>-<任务>/`，
左边「最近改动」点一下即可整批撤回。撤回不只是恢复素材 —— pool-map / manifest /
stories.ts / readings.ts 是管线产物，回滚后会自动重跑一次数据管线，保证撤回的服装阁
真的从清单里消失。

已知边界：collect-assets 直接写 `public/assets/**`，不在快照范围内。回滚后新阁转出的
几个 webp 会成为不被引用的孤儿文件（每个几 KB，不影响运行）。在意的话跑一次
`python tools/collect-assets.py --all --force` 重整。

## 为什么有时要重启模拟器

`vite.config.ts` 的 `watch.ignored` 把 `public/assets/**` 排除了（素材 470MB，不排除会把
文件监听打爆），所以新转的 webp 不会触发页面热更新。控制台的「完成后重启模拟器」
默认勾选；没勾的话，手动 `npm run dev` 重启一次即可。

## 目录

```
updater/
├── server.mjs     # HTTP 服务与 API
├── lib/           # 任务定义、元数据、素材归档、管线编排、DLC
├── web/           # 工坊界面（原生 JS，无框架）
└── dlc/           # 扩展包源区
```

加一种新更新（比如「新增货币道具」）只需在 `jobs.mjs` 的 `JOBS` 里加一项：
表单字段、素材槽位、写入逻辑。前端界面、预检、写入清单、快照全部自动跟上。
