# 心忆奇想工坊 · 使用说明

> 独立于抽卡模拟器的更新自助程序。把素材拖进来、填几个字，卡池 / 版本页 /
> 服装图鉴 / 故事图鉴 / 阅读物图鉴一起更新，写完自动跑数据管线。
>
> 素材版权归叠纸所有，本项目仅用于个人学习，非商业、非盈利。

## 启动

```bash
node updater/server.mjs          # 起服务并自动打开浏览器（http://localhost:5199）
node updater/server.mjs 5200     # 换个端口
UPDATER_NO_OPEN=1 node updater/server.mjs   # 不自动开浏览器
```

**零依赖**：整个程序只用 node 内置模块（`node:http` 静态服务 + SSE 日志），
不装任何 npm 包。Python 只被既有的素材管线用到（`python` / `py` / `python3` 会自动探测）。

它和模拟器互不影响：模拟器是 vite dev server（5178），更新工坊是 5199。
更新工坊只**读** `public/assets` 当皮肤（玄学运势的羊皮纸背景、`ui/btn` 图标、`sfx` 音效），
写入只发生在 `素材/` 与管线产物上。

## 三步用法

1. **选一件事**：左边挑「版本 / 卡池 / 套装 / 故事 / 阅读物」。
2. **填几个字 + 拖素材**：版本号、卡池名、套装名这些猜不出来的必须填；
   图片可以整套从资源管理器拖到页面上（或某个具体槽位），也可以把完整路径粘进
   底部的「按路径读取」输入框（支持一次多行、支持文件夹）。
3. **预检 → 写入并更新**：预检看缺什么；写入走「归档素材 → 跑数据管线 →
   （可选）重启模拟器 dev server」。全程日志在底部控制台实时滚动。

## 素材规格速查

拖进来的图按**尺寸 + 文件名**自动识别归类（识别不准的会进「待分配」手动指定）：

| 素材 | 规格 | 会被认成 |
|---|---|---|
| 版本缩略图 | 672×188 | `Card/T_UI_Friends_Card_img_NNN.png` |
| 版本大图 | 1532×860 | `Card/T_UI_Pear_Card_img_NNN_L.png` |
| 卡池背景 | 1920×1080（或 1000×500 列表图，自动裁 16:9） | `卡池背景图（纯图片，无艺术字）/list-<官方编号>.png` |
| 列表缩略图 | ≈320×140 | `source/<版本>·<名>/<池>/卡池横幅/列表缩略图.png` |
| 卡池名艺术字 | 横长透明图，文件名含 `_title` | `Pic/<编号>/T_UI_resonance_gacha_NNN_title.png` |
| 套装铭牌 | 332×96，文件名含 `name` | `Pic/<编号>/T_UI_resonance_gacha_NNN_nameNN.png` |
| 深海回响奖励 | 256×256，文件名「120抽-XXX」（20~100 抽全池共用一张，不用给） | `source/…/<池>/深忆奖励/` |
| 套装立绘 | 448×656 竖图 | `source/…/<池>/<套装>/套装立绘.png` |
| 进化立绘 | 文件名含「觉醒LV」或「进化LV」 | `source/…/<池>/<套装>/` |
| 部件图标 | 256×256，文件名 = 部件名 | `source/…/<池>/<套装>/部件图标/` |
| 属性文件 | `属性-*.yaml`（官方原样收） | `图片素材/<版本><名>/<星>星-<池型>共鸣-《套装》/` |
| 套装故事 | `.md` | `套装故事/故事-X星-<套装>.md` |
| 阅读物 | `.txt`（含【编号】头）或直接粘正文 | `阅读物/<分区>/<系列>/《书名》.txt` |

约定：

- **卡池内套装按「5★ 在前」填写顺序**，专属铭牌按这个顺序编号（name01 = 第一套 = 5★）。
- 版本卡编号、卡池编号（官方）**留空即自动取**（取当前最大值 +1）。
- 卡池的唯一编号就是官方 gacha 号（`banner-081`），**没有「版本内序号」这回事**了。
- 没给属性 yaml 时，会按部件图标生成最小版（部件名/部位齐全，五维空），图鉴里不会缺行。
- 没给卡池背景 / 艺术字不阻断更新，界面有兜底（深色渐变 / 纯文字标题），预检会提示。

## 写入了哪些地方

每个任务的「这次会写入」区块实时列出（随填写内容变化）。典型的一只新卡池：

```
素材/信息表/卡池索引.json            ← 新池登记（版本 / gacha 编号）
素材/信息表/套装序列.csv             ← 池内每套一行
素材/source/<版本>·<版本名>/<池名>/   ← 横幅 / 套装 / 深海回响奖励
素材/卡池背景图（纯图片，无艺术字）/list-<官方编号>.png
素材/0主素材/UI/SysResonance/texture/Pic/<编号>/   ← 艺术字 + 专属铭牌
素材/图片素材/<版本><版本名>/<星>星-限定共鸣-《套装》/    ← 属性 yaml
素材/pool-map.json · public/assets/** · src/data/*.ts   ← 管线产物
```

## 扩展包（DLC）

「更新」不再直接改共享的素材库 + 全量重建管线，而是产出一个**自包含的包**：

```
updater/dlc/<id>/        源包区（工坊编辑 / 打包 / 上传）
  dlc.json               清单：provides[]（接口声明）+ mount 决策
  data/<接口>.json       每个接口一份结构化数据
  assets/**              素材副本（已转码的 webp）

public/dlc/<id>/         运行区（模拟器运行时 fetch）
public/dlc/index.json    已装包索引 + 挂载开关
```

**包自带素材**，所以拷给任何装了本模拟器的人都能直接用，不依赖对方机器的素材库。

### 五个挂载接口

接口是包与模拟器之间**唯一的契约** —— 模拟器只认接口名，不认包内部结构。

| 接口 | 作用 | 挂载到哪 |
|---|---|---|
| `pool.banner` | 一整只卡池（含套装） | 共鸣页多一只池 |
| `pool.set` | 一套服装 | 指定卡池的套装列表 |
| `codex.story` | 一篇套装故事 | 故事图鉴 |
| `codex.reading` | 一篇阅读物 | 阅读物图鉴 |
| `version.banner` | 一个小版本（含缩略图 / 大图） | 版本页 |

**挂载决策有三层**（后者覆盖前者）：

```
运行区索引的接口级开关  >  包内 provides[].mount  >  默认挂
```

所以「装上但不生效」「只挂故事不挂套装」都能做到 —— 由包作者决定，也能在工坊里改。

### 用法

左栏最后一项「扩展包」：

1. **做一个包** —— 从库里切（卡池 / 套装 / 故事 / 阅读物 / 版本），自带素材副本；
2. **本机的包** —— 装 / 卸 / 打包 zip / 上传 / 删除，外加整包与每个接口的开关；
3. **云端 / 网盘** —— 配远端、上传、列远端包、下载并安装。

顶栏的**上传 / 下载**两个圆钮就是这块面板的快捷入口。

### 远端

| 类型 | 说明 |
|---|---|
| `local` | 本地目录（网盘同步盘 / 共享盘 / U 盘）。文件拷过去 + 自动维护 `index.json` |
| `http` | 通用 HTTP 端点：POST `/upload`、GET `/index.json`、GET `/<id>.dlc.zip` |
| `git` | git 仓库：`git add / commit / push` |

配置存 `updater/remote.json`（面板里可改）。

> ⚠ **git 远端目前还用不了**：本项目还没关联 git 仓库（`git remote -v` 为空）。
> 代码已写好，实际调用会明确提示「本项目尚未关联 git 仓库 ——
> 先执行：`git remote add origin <地址>`」，不会静默失败。关联之后即可直接用。

### 删除目录的正确姿势

⚠ **别直接用 `fs.rmSync(dir, { recursive: true })`**。

某些运行环境（WorkBuddy 的 safe-delete shim，通过 `NODE_OPTIONS` 注入）会把它改成
**回收站**语义：

- 删除变成**异步**的 —— 刚调完 `exists()` 目录还在，代码就误判成「删不掉」并抛错，
  但目录其实**已经空了**（表现为「接口报失败，目录却是干净的」）；
- 每个文件 ~260ms —— 一个 66 文件的 DLC 包要 **17~24 秒**；
- 偶尔整批失败（`Some operations were aborted`）—— 目录原封不动留在那儿。

✅ 统一用 `lib/dlc.mjs` 的 **`dlc.rmTree(dir)`**：按「原生子进程 → 直接 `rmSync`
→ 手写逐层 walk」三级递进，每级之后轮询确认目录**真的**消失才算成功。
实测 42 文件 246ms。

`uninstall()` 里也做了配套处理：运行区目录删不掉时**照样把索引条目摘掉**，
否则模拟器会读到一个「装了但文件不在」的包。

## 快照与回滚

每次「写入并更新」都会先把要改的文件原样备份到 `updater/.snapshots/<时间戳>-<任务>/`，
左边「最近改动」点一下即可整批撤回。撤回不只是恢复素材 —— pool-map / manifest /
stories.ts / readings.ts 是管线产物，回滚后会自动重跑一次数据管线，保证撤回的卡池
真的从清单里消失。

> 已知边界：collect-assets 直接写 `public/assets/**`，不在快照范围内。回滚后新池转出的
> 几个 webp 会成为不被引用的孤儿文件（每个几 KB，不影响运行）。在意的话跑一次
> `python tools/collect-assets.py --all --force` 重整。

## 为什么有时要重启模拟器

`vite.config.ts` 的 `watch.ignored` 把 `public/assets/**` 排除了（素材 470MB，不排除会把
文件监听打爆），所以新转的 webp **不会**触发页面热更新。控制台的「完成后重启模拟器」
默认勾选；没勾的话，手动 `npm run dev` 重启一次即可。

## 目录

```
updater/
├── server.mjs          # HTTP 服务 + API（state/inspect/upload/apply/rollback/dev/restart/thumb）
├── lib/
│   ├── util.mjs        # 路径 / 读写 / 图片尺寸解析 / CSV（零依赖）
│   ├── identify.mjs    # 素材识别：18 类，尺寸 + 文件名
│   ├── meta.mjs        # 版本表 / 卡池索引 / 套装序列 / 属性 yaml / 故事 / 阅读物
│   ├── archive.mjs     # 归档 + 快照 + 回滚 + 路径整理
│   ├── pipeline.mjs    # python 管线编排 + SSE 日志 + dev server 重启
│   ├── jobs.mjs        # 五类任务定义（界面与写入逻辑的唯一来源）
│   ├── dlc.mjs         # DLC 包：清单 / 索引 / 安装 / 卸载 / 挂载开关 / zip
│   ├── dlc-export.mjs  # 从库里切出自包含的包（五个接口各一个导出器）
│   ├── remote.mjs      # 远端适配器：local / http / git（列包 / 上传 / 下载）
├── web/                # 原生 JS 前端（无框架）：index.html / style.css / app.js
└── dlc/                # 扩展包源区（玩家自己的包，不随发行包分发）
```

加一种新更新（比如「新增货币道具」）只需在 `jobs.mjs` 的 `JOBS` 里加一项：
表单字段、素材槽位、写入逻辑。前端界面、预检、写入清单、快照全部自动跟上。
